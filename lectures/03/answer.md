## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回は講座固有の用語について一般的な回答しかできなかったが、エージェントは search_glossary ツールを用いて用語集を検索し、正確な定義を答えることができた。また、回答の末尾に関係する回を正しく出力した。
- `--trace` で見えたツール呼び出し（ツール名と引数）：search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'})
- 1つの質問での LLM 呼び出し回数（`requests`）：2
- 追加したツールと、docstring に書いた説明：追加したツールは make_quiz。docstringには「指定した回の用語から1つを選び、確認問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。」と記述した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：app/tools.py 内の search_glossary の docstring を「query には調べたい用語を1つだけ入れる」から「query には調べたい用語をまとめて入れる（例: "LORA QLORA"）」に変更し、uv run python -m app.agent --trace "LORA とQLORAの違いは?" を実行して変更前の挙動と比較した。
- 結果：ツールの呼び出し回数が2回（tool_calls=2）から1回（tool_calls=1）に減少し、search_glossary({'query': 'LORA QLORA'}) のように引数が1回にまとまって呼ばれるようになった。
- 気づき・疑問：docstring の記述（指示）を変えるだけで LLM のツール呼び出し行動を直接制御できることが確認できた。一方で、Python側の検索ロジックが複数キーワード検索に対応していない場合、結果が一部欠落する副作用が生じるため、プロンプト変更とあわせてツール内部の実装も整える必要があることがわかった。

- 取り組んだレベル：実装
- やったこと：app/tools.py に学習記録を保存する save_learning_log ツールを追加し、app/agent.py で requires_approval=True を付けてエージェントに登録した。また、承認待ちを扱うために output_type に DeferredToolRequests を追加し、動作確認を行った。
- 結果：エージェントは保存処理を勝手に実行せず、DeferredToolRequests(calls=[], approvals=[ToolCallPart(tool_name='save_learning_log', ...)]) を返して「利用者の承認待ち状態」で安全に一時停止した。
- 気づき・疑問：ファイルの書き込みや外部送信など取り消しにくい操作を行うツールには requires_approval=True を設定することで、AIが勝手に危険な操作を行うのを防ぐガードレール（Human-in-the-loop）を簡単に導入できることが理解できた。

- 取り組んだレベル：発展
- やったこと：Codespaces 環境にコーディングエージェント Pi をインストールして起動し、公開されている Pi のシステムプロンプト（system-prompt.ts）と自分のエージェントの INSTRUCTIONS を比較・分析した。
- 結果：Pi のシステムプロンプトには、ツール実行前に思考や計画を出力させる指示（Chain of Thought）、エラー発生時のリカバリ手順、コード修正時の制約（差分のみ変更するなど）といった暴走を防ぐガードレールが大量に定義されていることが確認できた。
- 気づき・疑問：実用的な自律エージェントを安定して動かすためには、単に役割や基本的な注意事項を与えるだけでなく、思考プロセスやエラー時の挙動、細かい禁止事項までシステムプロンプト側で厳密に制御する必要があることが理解できた。
